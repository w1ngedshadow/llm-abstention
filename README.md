# B2: отказ от ответа при неопределённости

Исследование робастной калибровки уверенности LLM и её применения к отказу от ответа при проверке утверждений по источникам.

**Цель проекта** — изучить выбранные работы по робастной калибровке, разобраться в теории и условиях применимости методов, реализовать подходящие методы и сравнить их на задаче проверки утверждений по источникам. Оценить, насколько полученные оценки уверенности помогают выбирать, когда модель должна отвечать, а когда — отказываться.

## План исследования

- **Исследовательский вопрос:** как выбранные методы калибровки влияют на качество оценок уверенности модели и соотношение между долей ошибок и долей выданных ответов? Насколько эти результаты устойчивы при изменении представления источника?

- **Существующие методы и статьи:** базовые подходы для сравнения — исходная уверенность модели и temperature scaling. Для изучения выбраны три работы:

  **[Expectation Consistency Loss (ECL), ICML 2026](https://proceedings.mlr.press/v306/dong26e.html)**  
  Метод предназначен для калибровки при изменении распределения данных и использует примеры нового распределения без правильных ответов. Мы разберём его теоретические условия и проверим применимость к переходу от текста к таблицам, затем сравним с temperature scaling.

  **[Thermometer, ICML 2024](https://proceedings.mlr.press/v235/shen24c.html)**  
  Метод обучает вспомогательную модель на нескольких задачах, чтобы калибровать уверенность LLM на новых задачах. Мы изучим механизм переноса и возможность использования для проверки утверждений; для полноценного воспроизведения одного VitaminC недостаточно.

  **[Generalized Venn and Venn-Abers Calibration, ICML 2025](https://proceedings.mlr.press/v267/van-der-laan25a.html)**  
  Метод выдаёт набор оценок вместо одной и при определённых предположениях обеспечивает гарантии калибровки на конечной выборке. Мы разберём эти гарантии и проверим, как применить подход к оценке правильности ответа и решению об отказе.

  Объём реализации каждого метода определим после разбора его требований к данным и применимости к нашей задаче.

- **Данные и проверка разметки:** основной датасет — VitaminC. Каждый пример содержит утверждение, текст источника и одну из трёх эталонных меток: `SUPPORTS` — подтверждается, `REFUTES` — опровергается, `NOT ENOUGH INFO` — недостаточно информации. Ответы модели оцениваются по разметке датасета. При подготовке выборок проверяются пересечения и связанные примеры, чтобы избежать утечки между настройкой и тестированием.

- **План экспериментов, включая новые форматы данных и абляции:**
  1. Подготовить воспроизводимый baseline: ответы без отказа, отказ по исходной уверенности и отказ после temperature scaling.
  2. Разобрать выбранные статьи и определить применимые методы.
  3. Реализовать методы и сравнить их с базовыми подходами.
  4. Оценить качество калибровки и соотношение риска и охвата.
  5. Проверить устойчивость при представлении одинаковых источников обычным текстом и Markdown-таблицами.
  6. Провести абляции отдельных компонентов реализованных методов.
  7. Проанализировать ошибки, ограничения и условия, при которых методы помогают или не дают улучшения.

  Методы сравниваются на одинаковых тестовых примерах. Данные для настройки калибровки и выбора порогов отделяются от данных для итоговой оценки. Протокол итогового сравнения фиксируется до основных экспериментов.

- **Модель и вычислительные ресурсы:** модель эксперимента — Qwen2.5-3B-Instruct. 

Основные метрики:

- **Ошибка калибровки (ECE)** — насколько оценки уверенности согласуются с фактической долей правильных ответов.
- **Риск** — доля ошибок среди ответов, которые система выдала.
- **Охват** — доля примеров, на которые система ответила.

Для сравнения методов используются диаграммы калибровки, кривые риска и охвата, а также доверительные интервалы. Целевые уровни риска и правила выбора порогов фиксируются в протоколах экспериментов. Достижение целевого риска на настроечной выборке само по себе не гарантирует его соблюдения на тесте.

Метка `NOT ENOUGH INFO` означает, что источник не позволяет подтвердить или опровергнуть утверждение. Это отдельный класс задачи, а не отказ системы от ответа.

## Воспроизведение

1. Установить зависимости: `python -m pip install -r requirements.txt`.
2. Подготовить данные по инструкции выбранного эксперимента.
3. Выполнить соответствующий ноутбук или скрипт с указанными настройками.
4. Построить таблицы и графики по сохранённым предсказаниям.

Для каждого эксперимента фиксируются:

- версия Python, зависимости и требования к оборудованию;
- модель, её версия, промпт и параметры запуска;
- версия датасета и правила формирования выборок;
- случайный seed;
- способ настройки калибровки и выбора порогов;
- команды запуска и расположение результатов.

Для начального эксперимента используются [описание baseline](report/baseline.md) и [ноутбук](results/baseline_vitaminc.ipynb). Инструкции для методов из статей будут добавляться по мере реализации.
