# B2: отказ от ответа при неопределённости

Исследование отказа LLM от ответа при проверке утверждений по источникам и робастной калибровки уверенности.

Статус: подготовлен работающий baseline, получены первые результаты. Реализованы отказ по исходной уверенности и temperature scaling. Собственный робастный метод находится на стадии планирования.

## План исследования

- **Исследовательский вопрос:** если калибратор уверенности и порог отказа настроены на знакомом формате источника с целевым риском 10%, сохраняется ли этот уровень ошибок при смене формата? Помогает ли робастная калибровка удерживать риск и какой долей ответов приходится за это платить?

- **Предполагаемый научный вклад:** исследовать настройку уверенности модели с учётом согласованности её предсказаний на разных представлениях одного источника. Проверить, помогает ли такая дополнительная информация сохранять качество калибровки и контролировать риск при смене оформления.

- **Существующие методы и статьи:** в baseline используются исходная уверенность модели и temperature scaling. Для дальнейшего исследования выбраны [Expectation Consistency Loss — ICML 2026](https://proceedings.mlr.press/v306/dong26e.html), [Thermometer — ICML 2024](https://proceedings.mlr.press/v235/shen24c.html) и [Generalized Venn and Venn-Abers Calibration — ICML 2025](https://proceedings.mlr.press/v267/van-der-laan25a.html).

- **Данные и независимая проверка разметки:** используется VitaminC с готовыми утверждениями, свидетельствами и эталонными метками. В baseline сохранены 657 примеров dev и 669 примеров test — по 200 групп `case_id`. Между dev и test нет пересечений по ID, группам и страницам Wikipedia. Ответы оцениваются по исходной разметке; ручная проверка подвыборки запланирована.

- **План экспериментов, включая новые форматы данных и абляции:** сравнить ответ всем, отказ по исходной уверенности, temperature scaling с отказом и собственный метод. Проверить обычный текст, Markdown-таблицы и дополнительные представления с тем же содержанием. Отдельно проверить вклад признаков согласованности. Для основных выводов использовать новые тестовые группы, не задействованные при оценке baseline.

- **Модель, вычислительные ресурсы и бюджет:** Qwen2.5-3B-Instruct без дообучения, с 4-битной квантизацией NF4. Baseline запускается локально на NVIDIA GPU с 8 ГБ памяти. Анализ сохранённых предсказаний выполняется на CPU. Платные API не используются; в дальнейших сравнениях будет учитываться число вызовов модели.

Основные метрики: риск — доля ошибок среди выданных ответов; охват — доля примеров, на которые система отвечает; ECE — ошибка калибровки уверенности. Температура и пороги фиксируются до тестирования. Метка «недостаточно данных» учитывается отдельно от отказа системы. Целевой риск на настроечной выборке не считается гарантией его соблюдения на тесте.

## Воспроизведение

- **Версия Python и окружение:** Python 3.11.10, Linux, сборка PyTorch с CUDA 12.6. Для полного запуска модели требуется NVIDIA GPU.
- **Установка зависимостей:** `python -m pip install -r requirements.txt`.
- **Подготовка данных:** использованные выборки сохранены в `data/baseline_dev.jsonl` и `data/baseline_test.jsonl`. Полный запуск ноутбука получает официальные данные через Hugging Face и повторяет отбор групп.
- **Запуск baseline и собственного метода:** открыть [`results/baseline_vitaminc.ipynb`](results/baseline_vitaminc.ipynb), установить корень репозитория рабочей папкой ядра и выполнить ячейки последовательно. Для анализа готовых CSV на CPU начать с раздела «Бейзлайн при разных целевых рисках». Собственный метод пока не реализован.
- **Построение таблиц и графиков:** выполняется в ноутбуке по сохранённым предсказаниям. Описание первых результатов находится в [`report/baseline.md`](report/baseline.md).
- **Настройки моделей и случайные seed:** seed 42, размер батча 2, квантизация NF4. Версии модели и датасета, промпт и параметры запуска зафиксированы в ноутбуке. При температурной калибровке dev разделяется на 100 групп для температуры и 100 групп для выбора порога.
